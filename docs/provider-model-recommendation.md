# 字幕翻译模型筛选与开发者推荐

当前策略由设置页和 popup 共用。模型发现仍读取用户 Key 对应的实时目录；候选筛选使用能力信息与专用模型规则；“开发者首选”由明确维护的清单决定，不根据 `mini`、`flash`、`latest` 等名称推测。

## 推荐清单

首选配置位于 `extension/provider_config.js` 的 `MODEL_RECOMMENDATIONS`，包含精确 API ID、原因、官方依据链接和最近复核日期。只有当用户账号的模型目录返回该模型且筛选为可选项时，界面才把它排在最前；界面不显示首选标记或额外说明，目录未返回时不替用户猜另一个模型。剩余兼容模型按 ID 稳定排序。

| Provider | 首选 API ID | 维护理由 |
| --- | --- | --- |
| OpenAI | `gpt-6-luna` | 官方将其定位为高效率、面向高频工作负载；符合批量字幕的成本与吞吐取向。 |
| Gemini | `gemini-3.5-flash-lite` | 官方描述为低延迟、高吞吐、低成本；支持文本输入与文本输出。 |
| DeepSeek | `deepseek-flash` | DeepSeek 当前将该 API ID 指向 V4.1 Flash，并说明其架构面向更高推理速度与吞吐。 |

这些是开发者默认首选，不代表本项目已对三者做过同一字幕集的质量、延迟和费用实测。官方产品定位提供选择依据，但不能保证每个账号的权限、限额和实际速度。

## 默认配置与目录边界

上述三个 ID 也作为新配置的 provider 默认模型。此前动态目录版本里模型仍为空的 profile 会补上对应默认值；用户已保存的非空模型选择保持不变。用户切换 provider 时读取各自 profile，不共用 Key 或模型。

模型目录仍然是用户可选项的来源。未知模型不会因不在推荐清单而被过滤；它会按能力信息和当前请求协议标记为 candidate、unknown 或 incompatible。推荐项也不能绕过不兼容筛选，或代表翻译验证成功。若当前账号目录没有返回默认模型，配置里的默认 ID 仍可手动验证；界面不会把目录中的其他模型冒充首选。

明确的生图、生视频、TTS、转录、Realtime、embedding、rerank 和 moderation 专用模型默认隐藏；文本输入/输出的通用多模态模型继续保留。只在能力信息明确表明不支持文本或当前 provider 接口时判不兼容；信息不足就保留为未知模型。设置页和 popup 共用这一逻辑。

## 维护约定

模型版本或 API 别名变化时，开发者更新 `MODEL_RECOMMENDATIONS` 的精确 ID、理由、官方来源和 `reviewedAt`，并确认目录返回的 ID 与翻译调用接口一致。推荐名单只决定默认首选和展示顺序，不构成 API 可用性白名单。

没有真实 API Key 的情况下，目录和翻译验证只能做 mock 测试。用户 Key、代理与账户等级会影响模型可见性、调用权限与吞吐。只有“验证服务”对用户当前配置实际发出翻译请求并成功，才显示该配置的翻译验证通过。
